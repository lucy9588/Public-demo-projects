02
Case Study

Diagnostic Log Collection & Secure Vendor Upload Automation

Question

How can diagnostic logs be collected, transferred, and uploaded to a vendor through a repeatable and controlled workflow instead of relying on manual handoffs?

Approach

I designed the workflow as an end-to-end automation chain: user input, API trigger, log collection, staging transfer, credential handling, network routing, and vendor upload.

Demonstrates

End-to-end ownership, automation design, secure transfer thinking, API orchestration, and production release capability.

Input API Trigger Collect Logs Transfer Upload
End-to-End Design FastAPI AAP / AWX Ansible Secure Transfer Vendor Upload
+ View detailed flow

Project context

This project automated the full process of generating diagnostic logs, transferring them through a controlled staging path, and uploading the final package to a vendor destination. I owned the work from design, testing, validation, and release, instead of only implementing one isolated script.

My Role

I designed the workflow, built and tested the automation path, validated network connectivity, coordinated dependencies, and supported production release.

Core Problem

The previous process depended on manual log gathering, manual transfer handling, credential coordination, and multiple handoff points.

Functional flow

The functional flow describes the business execution sequence from user request to final vendor upload. The key design goal was to make the process predictable, repeatable, and easier to operate.

Step 01 User Input User provides product, operation, location, host, and required parameters.
→
Step 02 Automation Trigger The automation platform receives the request and starts the selected template.
→
Step 03 Log Collection Target diagnostics are collected from the relevant runtime environment.
→
Step 04 Staging Transfer The generated package is transferred to a staging host through a controlled path.
→
Step 05 Vendor Upload The package is uploaded to the vendor endpoint using the approved outbound route.

Design Point

I separated the workflow into clear stages so each step could be validated, tested, and troubleshot independently.

Operational Value

The process became easier to repeat, easier to audit, and less dependent on individual memory or manual coordination.

Code flow

The code flow connects the input layer, backend API, automation middleware, and execution template. This layer turns a user request into a controlled automation run.

Input Layer Form / Request Body Collects structured inputs such as vendor, product, operation, host, and parameters.
→
API Layer FastAPI Endpoint Receives the request and normalizes the payload for the automation service.
→
Service Layer Middleware Logic Resolves the correct execution path, template, and runtime inputs.
→
Execution Layer AAP / Ansible Runs log collection, file preparation, transfer, and upload tasks.
→
Output Layer Execution Result Returns run status, generated files, transfer result, and upload completion output.

What I Designed

I mapped user inputs to backend request structure, defined execution parameters, and aligned the API behavior with the automation template.

Why It Matters

This made the process repeatable. The same input model leads to the same execution path, reducing inconsistent manual operation.

Network flow

The network flow shows how the collected log package moves from the source environment to the staging server and then to the vendor endpoint through the approved connectivity path.

Source Linux Host The diagnostic logs originate from the target runtime host.
→
Internal Transfer Staging Server The generated archive is placed on the staging server for controlled onward transfer.
→
Control Point Firewall / Infra Rule Connectivity is restricted by approved source, destination, and port rules.
→
Outbound Route Proxy Rule The upload exits through a managed proxy path for the vendor transfer.
→
Destination Vendor SFTP The final diagnostic package is delivered to the external vendor endpoint.

Network Consideration

The upload path had to respect enterprise connectivity rules, staging design, outbound proxy routing, and secure credential handling.

My Validation Work

I tested the transfer chain, validated the staging behavior, checked the outbound route, and confirmed the final upload behavior before release.

Supporting components

The solution involved multiple supporting systems. The important design challenge was coordinating them into one clean execution path.

Orchestration AAP / AWX Triggers and controls the automation run.
Input Source Inventory / Parameter Service Provides target host and runtime metadata.
Security Credential Services Provides temporary credentials and upload secrets.
Visibility Execution Insight Captures execution status and operational evidence.

Outcome

The project converted a multi-step manual operation into a repeatable automated workflow. It also demonstrated my ability to connect process design, code orchestration, network constraints, secure transfer, testing, and release ownership.

Result highlights

  • Designed the full functional workflow from request to vendor upload.
  • Built and tested the code path connecting API input with automation execution.
  • Validated the staging, firewall, proxy, and final upload route.
  • Reduced manual handoffs and improved repeatability.
  • Owned the project from design and testing through production release.
