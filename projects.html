Azul Java Provision Automation

Question

How can Java provisioning become faster, safer, and more consistent across target servers without relying on repeated manual installation steps?

Approach

I designed a request-driven automation workflow that validates inputs, resolves package and inventory details, triggers provisioning, configures the runtime environment, and verifies the final installation.

Demonstrates

Provisioning automation, input validation, platform orchestration, environment configuration, installation verification, and operational consistency.

User Request Validate Resolve Package Trigger Automation Install Verify Return Result
Java Provisioning Azul Java FastAPI Jenkins / AAP Ansible Target Server
+ View project flow

This project automates Azul Java provisioning across target servers through a controlled request and execution workflow. The process starts with a user request containing the target server, environment, Java version, and installation type. The platform then validates required fields, checks server and environment eligibility, resolves the package source and runtime inventory, and triggers the provisioning automation through Jenkins / AAP. On the target server, the workflow installs Azul Java, configures environment settings such as JAVA_HOME, profile, alternatives, or symlinks, and verifies the installation by checking the expected Java version. The final result is returned with success or failure output, making Java provisioning more standardized, auditable, and consistent across environments.

This project redesigned the Ubuntu base image refresh workflow for CVE remediation. The diagram shows the before-and-after process clearly: in the previous workflow, image refresh depended on manual cyberflow scanning, prerelease handling, CR approval, and release execution, which added significant delay. Server Lease Renewal Automation

Question

Which parts of server lifecycle work should be automated, and which parts still need human checkpoints?

Approach

I examine lifecycle work as a sequence of preparation, validation, execution, verification, and rollback awareness.

Demonstrates

Systems thinking, change safety, repeatable operational design, and validation discipline.

Prepare Validate Execute Confirm Rollback Awareness
Change Safety Lifecycle Thinking Validation Repeatability
+ View project flow

This project automated the lease checking and renewal process for DEV and UAT virtual machines. The workflow validates server IDs, separates invalid inputs from eligible servers, calls the getLease API to check current lease status, and handles the asynchronous API job through polling, waiting, retrying, and fallback verification. If a server is eligible for renewal, the pipeline calls the extend lease API, monitors the renewal job until completion, verifies that the new lease time is later than the old lease, and then sends a final email notification. The design reduces manual lease checking, prevents unnecessary API calls from invalid inputs, standardizes DEV and UAT renewal behavior, improves failure visibility, and helps avoid testing interruption caused by expired non-production servers.
